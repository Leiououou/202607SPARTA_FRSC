2026-07-28: independent constant-gamma surface reaction style

Source:
- Added src/surf_react_gamma.h and src/surf_react_gamma.cpp.
- Registered SurfReactStyle(gamma,SurfReactGamma) through the normal generated
  style-surf-react include mechanism.
- Did not modify surf_react_adsorb.cpp or surf_react_adsorb.h for this work.

Command:
  surf_react ID gamma file surf|face Tw n_site
    [init_cover species fraction]...
    [tally_only yes|no]
    [species gamma]...

Behavior:
- Exactly two unordered reactants and one gas product per file reaction.
- Missing species coefficients default to zero.
- Gamma-gated vacancy samples adsorb the incident species.
- Gamma-gated occupied matches consume one surface species and diffusely emit
  the sole product at Tw.
- Adsorption is not a reaction tally.
- tally_only counts occupied-site matches but does not execute chemistry.
- h is J per physical reaction; reaction heat and particle energy difference
  enter existing compute boundary/surf echem and etot paths.
- No PS clock and no nsync keyword.

Parallel state:
- Face deltas use MPI_Allreduce every timestep.
- Explicit-surface deltas use Surf collate/spread operations.
- Replicated and explicit/distributed surface storage are supported.
- Explicit custom attributes are namespaced by reaction ID.

Validation:
- Windows MinGW serial build linked src/spa_serial.exe.
- WSL MPI build linked src/spa_mpi.
- Deterministic face adsorption, recombination, tally-only, default-zero, and
  heteronuclear order-symmetry cases passed.
- gamma=0.5 gave 1557/3174 = 0.4905 candidates in serial.
- Positive, zero, and negative h shifted echem and etot with the expected sign.
- Replicated explicit surf converted 992/1000 O to exactly 992 O2.
- Two-rank split-grid face gamma=0.5 gave 1514/3134 = 0.4831 candidates.
- Two-rank mutating face produced exactly 3120 O2 for 3120 reactions.
- Two-rank replicated explicit surf produced 990 O2 for 990 reactions.
- Two-rank distributed explicit surf produced 991 O2 for 991 reactions.
- Comment handling passed; duplicate unordered pairs, missing heat, and
  multi-product formulas were rejected.
- Existing adsorb GS/PS tally-only parser/runtime regression passed.

2026-08-04: strict one-site option

Command extensions:
- Added an optional keyword immediately after the style:
    surf_react ID gamma only_one no file surf|face Tw n_site ...
    surf_react ID gamma only_one yes file surf|face Tw ...
- Omitting `only_one` is identical to `only_one no` and preserves the original
  parser and n_site-based behavior.
- `only_one yes` omits n_site, starts every site vacant, and rejects
  `init_cover`.

Behavior and parallel consistency:
- `only_one yes` assigns exactly one global state slot to every explicit surf
  element or box face.
- The state owner is unique across MPI ranks. Gamma-gated collisions serialize
  read/modify/write access with an exclusive passive-target MPI window lock.
- A surf spanning more than one grid partition therefore remains one physical
  site instead of silently becoming one site per process.
- An empty site adsorbs the incident species. An occupied mapped pair reacts.
  An occupied unmapped pair releases the stored species and diffusely scatters
  both particles.
- Existing n_site delta/collate behavior is unchanged for `only_one no`.
- No changes were made to surf_react_adsorb.cpp or surf_react_adsorb.h.

Validation:
- Clean WSL MPI build completed after the class-layout header change.
- Deterministic adsorption/reaction and unmatched-pair serial tests passed.
- Explicit `only_one no` compatibility and replicated-surf tests passed.
- Shared box-face and explicit distributed-surf stress tests passed on 2 and
  4 MPI ranks.
- A four-element coarse surface spanning MPI grid partitions completed 57,092
  surface collisions and 9,892 reactions on 2 ranks without a negative count,
  capacity overflow, hang, or MPI-dependent duplicate site.

2026-08-04: multi-node MPI RMA synchronization fix

- Administrator logs identified MPI_ERR_RMA_SYNC in MPI_Win_sync during
  one-site window initialization on a 256-rank multi-node UCX run.
- Removed MPI_Win_sync outside a passive-target epoch.
- Window initialization now zeroes each rank's owned slots with a self-target
  MPI_Put enclosed by MPI_Win_lock/MPI_Win_unlock.
- The RMA window stores one integer per global surface; it does not contain
  grid cells, surface2grid maps, or migration data.
- A clean MPI build and four serial regressions passed.
- Shared-face, distributed-surf, and coarse cross-partition tests passed on
  2 and 4 MPI ranks after the fix.

2026-08-05: gank compatible per-species inventory mode

Command extensions:
- Added `gank no` as an explicit alias for the unchanged n_site path.
- Added:
    surf_react ID gamma gank yes every_n N allow|noallow
      file surf|face Tw [tally_only yes|no] [species gamma] ...
- Omitting both `gank` and `only_one` still selects the original n_site mode.
- `gank yes` omits n_site, rejects init_cover, and starts all inventories at
  zero. It is a separate mode from only_one.

Behavior:
- Every surface has one independent DSMC-particle inventory for each surface
  reactant species.
- Compatible stored partners are selected with probability proportional to
  their inventory count; a compatible reaction always precedes capacity
  handling.
- `allow` stores an unbounded 64-bit count with capacity interpreted in
  logical chunks of every_n; it performs no dynamic MPI allocation.
- `noallow` stores up to every_n particles per species. A further unmatched
  same-species arrival removes one stored particle and diffusely scatters both
  particles, leaving the inventory at every_n-1.
- Positive-gamma species without any positive-gamma mapped partner are
  rejected during initialization.

Parallel state:
- The unique owner of every face or explicit surf stores a 64-bit inventory
  vector in an MPI RMA window.
- One exclusive passive-target lock covers the complete weighted partner
  selection and read/modify/write update.
- Authoritative inventory vectors are mirrored to existing custom state
  arrays each timestep for output and diagnostics.

2026-08-05: independent per-species inventory output

- `compute surf` remains unchanged; gank inventory is a surface state rather
  than a collision-event tally.
- For explicit surfaces, use `s_gamma_ID_species[*]` in `dump surf` to write
  one instantaneous raw DSMC inventory count per surface species to a separate
  file. `s_gamma_ID_total` is available when a total column is also desired.
- Gamma initialization now prints every dump field and its species mapping.
  The order follows the selected species in the SPARTA species list.
- MPI dump row order may differ from surface-ID order, so output examples keep
  the `id` field and post-processing must match by ID.
- A deterministic four-species explicit-surface test produced
  `C=1, O=0, N=1, CO=1` on the impacted surface in serial, 2-rank, and 4-rank
  runs; all other surfaces remained empty.

2026-08-05: optional noleave behavior

- Added the bare `noleave` keyword after the selected nsite, only_one, or gank
  mode clause and before the reaction filename.
- In nsite and only_one modes, an incompatible impact no longer releases the
  selected resident; only the incident particle scatters.
- In gank noallow mode, an unmatched arrival at full same-species capacity no
  longer removes one stored particle; inventory remains full and only the
  incident particle scatters. Compatible-first matching and normal adsorption
  below capacity are unchanged.
- Omitting `noleave` preserves all previous release behavior and input syntax.
- Added deterministic serial coverage for all three modes.
